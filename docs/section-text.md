# 正文区段文本格式

正文编辑器的“导入 / 导出区段文本”可以粘贴 Markdown/Kramdown 或选择 UTF-8 `.md` / `.txt` 文件并预览追加，也可以下载已保存正文的 `.md` 文件。导入只追加；整篇替换和逐文件冲突合并不属于这个入口。原有区段保持身份、内容和顺序。

## 封套与字面文本

每个文件以一行标准分割线、紧邻的一行 Kramdown IAL，以及一个 LF 开始。IAL 描述后面的文件。导出使用 `---`，导入接受最多三个空格缩进的星号、连字符和下划线标准分割线，标记之间可有空格或 Tab。没有起始封套的普通文本成为默认 Kramdown 文件；空输入是零文件，显式封套允许空文件。

```text
---
{: file-id="10000000-0000-4000-8000-000000000001" file-kind="file" content-type="text/x-kramdown" edit-mode="whole-file"}
第一个文件的正文

---
{: file-id="10000000-0000-4000-8000-000000000002" file-kind="file" content-type="text/x-kramdown" edit-mode="whole-file"}
第二个文件的正文
```

每个后续封套前恰好一个 LF 属于传输格式。导出器总是单独添加这个 LF，不借用内容自己的行尾；导入器只消费这一个 LF。上例第一份文件的正文末尾仍有一个 LF。最后一个文件后不追加格式换行。正文中的 NBSP、尾空行、Unicode 组合形式和空文件均保留。传输统一 UTF-8/LF：CRLF 和单独 CR 转成 LF，不做 Unicode 正规化；孤立代理项会报错。

边界扫描只识别公共文件词法：最多三个空格缩进的反引号/波浪号围栏，关闭标记须同字符且不短于开启标记。围栏内部的分割线和 IAL 属于正文。未闭合围栏会遮蔽后续文件头，因此直接拒绝。主体不解析 Markdown 容器、列表、表格或适配器的行内语法。围栏外的分割线紧邻 IAL 是保留结构，普通文件保存不能用它新增区段。非法 IAL 外壳、引号和重复属性会报告原文行号。

## 文件属性与适配器匹配

| 属性 | 含义 |
| --- | --- |
| `file-id` | 稳定文件 UUID；未提供时新建，提供但无效或在源中重复时拒绝 |
| `file-kind` | `file` 或 `layout` |
| `content-type` | 适配器文件内容类型 |
| `edit-mode` | 互斥的 `whole-file` 或完整 `crdt` |

`#anchor` 和普通 `id` 属性属于外来 Kramdown 属性，不充当文件 UUID。命名属性、`.class`、`#anchor` 和 IAL 引用 token 都会保留；引用不被展开或执行。导入原始封套保存在文件的 `sourceIal` 元数据中。区段编辑器依然只通过文件句柄读写正文文本，不获得这些属性、UUID 或宿主命令接口。

只有 `file-kind`、`content-type` 和 `edit-mode` 全部准确匹配，才选择专门实现：

| 文件类型 | 编辑模式 | 内容类型 | 导入行为 |
| --- | --- | --- | --- |
| `file` | `whole-file` | `text/x-kramdown` | 默认 Kramdown 完整文件 |
| `file` | `crdt` | `text/plain` | 从文本创建新的完整协作状态 |
| `layout` | `whole-file` | `application/vnd.kinship.layout+json` | 校验并读取布局文件自己的引用文本 |

其余合法但不完整/未知的声明使用默认 Kramdown，保留原文和属性。导出时只更新其 `file-id`，不补齐原声明使其下次导入意外启用专门适配器。封套属性间的空格可以规范化，原属性值和 token 保留。

导出按根文件和布局槽位的遍历顺序排列扁平文件。导入从布局自身的引用推导根文件，不增加通用 `children`。缺失引用、重复容纳、循环及超过 64 层的布局全部拒绝。选择复制时为全部文件分配新 UUID，只重写布局实现声明的文件引用，不扫描或改写普通正文中的 UUID/链接。

## 预览、提交与范围

`DataAdapter.previewDocumentText` 经 `POST /rpc/v1/documents/text/preview` 解析文本，并在一致只读快照中核对目标概念版本及所有文件身份。预览只返回候选正文，不写入工作区。保留身份时，任何已用 UUID 或墓碑均阻止追加；复制是明确的重新预览选择。源文件内部的重复 UUID 即使复制也拒绝，因为布局引用存在歧义。

`DataAdapter.previewDocumentTextFile` 将文件作为 multipart POST 发往 `/rpc/v1/documents/text/file`。UI 不解码文件；后端校验真实文件名、原始字节长度和 SHA-256，再以 fatal UTF-8 解码复用同一个文本预览。无效编码会报错，输入文件保留供重选；空文件产生零区段，明确的空封套仍产生一个空文件。解码保留初始 U+FEFF，与文本粘贴一致，不静默消费 BOM。响应核对文件摘要、名称、长度和目标，防止把另一文件的预览当成本次结果。切换导入来源、文件或身份模式都会使旧预览失效。

确认追加复用现有 `saveBody → POST /rpc/v1/commands/apply → concept.updateFields`，检查预览时的概念版本。已有文件不能被改写。内容、文件身份、可信编辑者、前值和幂等结果在同一事务保存；预览过期需要重新核对。结果不明时保持原命令和候选文件 UUID 重试，不重新解析并创建另一批文件。导出前及确认导入前，都经过区段生命周期守卫；未保存草稿或未确认的 CRDT 更新会阻止继续。

`DataAdapter.exportDocumentText` 经 `POST /rpc/v1/documents/text/export` 读取已保存的一致版本。文本格式不包含原 CRDT 因果状态、编辑历史或媒体字节；协作文件再次导入时从文本初始化，不能用于恢复旧协作会话。当前 JSON 图谱包仍可携带区段的二进制协作状态；其覆盖范围也不包含完整历史和媒体。

单份区段文本最多 1 MiB UTF-8，最多 10,000 个文件；单行 IAL 最多 8192 字符和 128 个 token；预览/导出 JSON 结果最多 2 MiB。超额明确报错，内容不会被截断。大文档分页、纯 Markdown/Wiki 语义转换及完整历史归档另行实施。
